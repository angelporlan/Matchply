# Límites de peticiones costosas

Las políticas de `src/lib/product-rate-limit.ts` limitan por IP antes de autenticar o leer el cuerpo, y después por el actor verificado (cuenta o invitado). Cubren creación de sesión invitada, optimización y variantes, importación y descubrimiento de ofertas, matching, investigación, perfil, outreach, networking, lectura/importación de CV y fotos. La extensión conserva además sus límites por token y usuario. La API de agente conserva sus límites por IP, clave y cuenta.

La IP se toma de `X-Real-IP`, que Nginx sustituye por la conexión real; si falta se usa el último valor de `X-Forwarded-For`, añadido por ese proxy. Nunca se usa el primer valor que puede suministrar el visitante. Las claves de IP de las políticas de producto son hashes en memoria. Las respuestas limitadas son HTTP 429 con un mensaje público y `Retry-After` en segundos; las rutas de fotos conservan su código `PHOTO_RATE_LIMIT` y las acciones de servidor devuelven un código legible. Se mantienen los límites más estrictos previos de importación y descubrimiento para invitados.

El contador usa un mapa acotado compartido en el proceso web, adecuado para la instalación actual de una instancia. Reiniciar el proceso reinicia las ventanas y múltiples réplicas no comparten contadores; antes de escalar a varias instancias debe sustituirse por un almacén compartido. La web debe permanecer detrás del proxy confiable y no exponerse directamente, pues las cabeceras no son fiables fuera de ese límite. Las cuotas de uso y la idempotencia de IA siguen siendo controles independientes.
